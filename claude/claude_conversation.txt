|---|---|

**The part that makes training interesting: where the negatives come from**

In a contrastive setup, a negative is a passage the model learns to push away from the question.
- The dense retriever only ever sees passages that BM25 already let through. Train it on negatives taken from BM25's top N ("hard negatives"), not random passages. That way it learns to separate passages that look similar on keywords, which is its actual job in the cascade.
- Do the same for the reranker, using negatives from the dense retriever's top k.

You can call this cascade-aware training: each stage trains on the output of the stage before it. Compare it against random negatives as an ablation.

## How novel is it?

**Medium. I'd guess roughly 10–14 out of 20 for novelty.** That's my estimate, not something from the marking guide.

- **Not new:** the three-step pipeline itself (keyword search, then a meaning-based search, then a reranker). Lots of companies already use this exact setup.
- **Not new:** training the meaning-based search with tricky wrong passages taken from keyword search. A well-known 2020 paper (DPR, Karpukhin et al.) already did this.
- **Somewhat new:** the experiments that measure where the pipeline breaks:
  - how many right passages the keyword step throws away before the later steps ever see them
  - whether that happens more when the question uses different words from the passage
  - whether the reranker's score can tell you "none of these passages answer the question, so don't answer"
  - how the pipeline behaves when the passages are missing, unrelated or contradict each other

The markers care most about that last group. The pipeline alone gets few novelty marks. The experiments about when and why it fails are what earn them.

## What training needs to be done

Only **two models get trained**. The keyword search (BM25) does no learning. It just counts matching words.

### Model 1: the meaning-based search (dense retriever)

**What it does:** it turns every question and every passage into a list of numbers. Questions and passages with similar meaning get similar numbers. To search, it picks the passages whose numbers are closest to the question's numbers.

**Why train it:** the downloaded version was trained on general text. It hasn't seen your type of questions.

**How to train it:**
1. Take a question from the training data.
2. Take the correct passage for that question.
3. Take some wrong passages that keyword search ranked highly. They share words with the question but don't answer it, which makes them hard to tell apart from the right one.
4. Adjust the model so the question's numbers move closer to the correct passage and further from the wrong ones.
5. Repeat for thousands of questions.

### Model 2: the reranker

**What it does:** it reads the question and one passage together and gives a score for how well the passage answers the question. It is slower than Model 1, so it only checks the few passages Model 1 picked.

**Why train it:** same reason as Model 1. It was trained on a different kind of question.

**How to train it:**
1. Take a question.
2. Pair it with its correct passage, labelled "yes".
3. Pair it with wrong passages that Model 1 ranked highly, labelled "no".
4. Adjust the model so it scores "yes" pairs high and "no" pairs low.
5. Repeat for thousands of pairs.

### Rules for training

- Train on the **train** data only. Test on a separate set the models never saw.
- Before training, drop any "wrong" passage that actually contains the answer. Otherwise the model learns that right passages are wrong.
- Each model takes about 30–60 minutes on a free Colab GPU.

### Then compare

Run the whole pipeline four ways:
1. Neither model trained
2. Only Model 1 trained, using random wrong passages
3. Only Model 1 trained, using tricky wrong passages from keyword search
4. Both models trained, using tricky wrong passages

That shows how much each piece of training actually helped.

## Ways to improve faithfulness

| Technique | What it does | Training? | Effort |
|---|---|---|---|
| **Prompting** ("only use the passages", "quote then answer") | The instruction alone | No | Very low, use as a baseline |
| **Context-aware decoding (CAD)**, Shi et al. 2023 | Gets the model's word probabilities with and without the passages, then boosts the words the passages pushed it towards. The answer leans on the passages instead of the model's memory | No | Low |
| **Answer, then verify with NLI** | A small NLI model checks whether a passage supports the answer. If none does, retry or abstain | No (pretrained NLI) | Low |
| **RAFT**, Zhang et al. 2024 | Fine-tunes the model on questions mixed with unrelated passages so it learns to ignore them and quote the relevant one | Yes, LoRA | High |
| **Knowledge-conflict training**, Longpre et al. 2021 | Fine-tunes on passages with deliberately changed facts so the model follows the passage over its memory | Yes | High |

## Ways to improve abstaining

| Technique | What it does | Training? | Effort |
|---|---|---|---|
| **Prompting** ("say unanswerable if…") | Baseline | No | Very low |

Agreed. The handout says "develop and evaluate a method", so you need one method that's yours, not just a comparison of existing ones. Here's a proposal that builds on everything we've discussed.

## Your method: reranker-guided generation

The core idea: **the reranker's score tells the language model how much to trust the passages.** None of the existing methods we covered connect those two things. Your method has three parts:

**Part 1: Evidence selection (trained)**
BM25 → top N → your fine-tuned dense retriever → top k → your fine-tuned reranker. Keep only passages that score above a set cut-off.

**Part 2: Abstain gate**
If even the best passage scores below a threshold τ, the model answers "I don't have enough evidence" and doesn't generate an answer.

**Part 3: Adaptive CAD (your main change)**
Standard CAD always boosts the passages by the same fixed amount (α). That hurts when the passages are weak or wrong. In your version, **α depends on the reranker score**: strong passages get a strong boost, borderline ones get a weak boost, and passages below τ have already been handled by Part 2.

Optional extra for contradictions: an NLI model checks whether the top 2 passages contradict each other. If they do, the model either abstains or answers from the higher-scored passage, and you can test both choices.

**What gets developed and trained**
- Fine-tuning the dense retriever and reranker with tricky wrong passages
- The rule linking the reranker score to α (for example, α = α_max × the reranker's score squashed into the 0–1 range)
- τ and α_max, tuned on a **validation** set, not the test set

## How you evaluate it

**Baselines**
1. Naive retriever + normal generation + abstain prompt
2. Naive retriever + standard CAD with a fixed α
3. Your pipeline + normal generation

**Ablations** (remove one part at a time to show what each one contributes)
- Without the abstain gate
- Fixed α instead of adaptive α
- Pretrained retriever and reranker instead of your fine-tuned ones
- With or without the contradiction check

**Test conditions:** good, incomplete, irrelevant and contradictory passages.

**Metrics**
- Accuracy (EM/F1) on answerable questions
- Faithfulness: the share of answers supported by the passages, checked with NLI
- Abstention precision and recall, plus a risk–coverage curve
- Latency

## How it scores

=== CLAUDE (2026-11-11 04:13 UTC) ===
Standard CAD (context-aware decoding) is from Shi et al. 2023, *"Trusting Your Evidence: Hallucinate Less with Context-aware Decoding"*.

## The problem it fixes

A language model writes an answer one word at a time (strictly, one token at a time). At each step it gives a probability to every possible next word. Those probabilities come from two places:
- **the passages** you gave it
- **its memory**, meaning everything it learned in training

When the two disagree, memory often wins, so the model ignores the passage and states what it "remembers". That's an unfaithful answer.

## What CAD does

At every word, CAD runs the model **twice**:
1. **With** the passages and the question
2. **Without** the passages, question only

The second run shows what the model would say from memory alone. CAD then boosts the words whose probability went **up** because of the passages and cuts the words that come from memory alone.

The formula, for each candidate word:

> score = P(with passages)^(1+α) ÷ P(without passages)^α

**α** sets how strongly it pushes towards the passages. α = 0 is normal generation, and larger α means a stronger push. The paper uses one fixed α for every question.

## Worked example (α = 1)

Question: "Who is the CEO of Company X?" The passage says **Alice**. The model's memory says **Bob**, from old training data.

| Next word | P(with passages) | P(without passages) | Normal model picks | CAD score = P_with² ÷ P_without |
|---|---|---|---|---|
| Alice | 0.45 | 0.05 | | 0.2025 ÷ 0.05 = **4.05** |
| Bob | 0.50 | 0.90 | ✅ Bob (0.50 > 0.45) | 0.25 ÷ 0.90 = **0.28** |

- **Normal model:** says **Bob**, because memory slightly outweighs the passage.
- **CAD:** says **Alice**. Alice's probability jumped from 0.05 to 0.45 when the passage was added, so CAD treats Alice as coming from the passage and boosts it.

## Its weaknesses, which your method targets

- **α is fixed.** CAD pushes towards the passages equally hard whether they're good, irrelevant or wrong.
- **If the passage is wrong, CAD makes it worse.** If the passage wrongly says "Carol", CAD boosts Carol just as strongly.
- **It never abstains.** It always produces an answer.
- **It's slower.** It runs the model twice per word, so generation takes about 2× as long.

Your adaptive version fixes the first three. The reranker score sets α, so trusted passages get a strong push, weak ones get a gentle push, and passages below the threshold lead to an abstention instead of an answer.

## 1. The reranker doesn't decide what's true

That deals with **incomplete** and **irrelevant** passages, which the reranker can detect. **Contradictory** passages need a separate check.

## 2. What happens with two passages that contradict each other

- Passage A: "Alice became CEO of Company X in 2023." → reranker **0.92**
- Passage B: "Carol became CEO of Company X in 2023." → reranker **0.90**

The reranker scores **each passage separately**, never side by side, so it never sees that they conflict. Both score high, both go to the model, and adaptive α gives a **strong** push towards the passages. The model then picks one, often depending on which passage comes first, or mixes them up, and it sounds confident. Your method makes this case **worse**, not better. That's expected, and it's a useful failure case to report.

## Fixing it: a conflict check

Add a separate step that looks at the high-scoring passages **together**. Two ways to do it:

| Option | How it works | Pros and cons |
|---|---|---|
| **A. Answer-disagreement check** | Have the model answer from each top passage on its own. If the answers differ ("Alice" vs "Carol"), flag a conflict | Simple and reliable, but costs a few extra model runs |
| **B. NLI check** | An NLI model compares the passages directly: contradiction, agreement or neutral | Fast, but weaker on long passages and often marks unrelated passages as "neutral" |

I'd recommend **A**.

**When a conflict is flagged**, test two behaviours:
- **Abstain:** "The sources disagree."
- **Report both:** "Sources disagree: one says Alice, another says Carol."

Don't try to pick the "true" one. You can't check that, and a system that admits a conflict is more faithful than one that guesses.

## How the full method handles each condition

| Condition | Which part handles it |
|---|---|
| Good passages | Reranker scores high, strong α, normal answer |
| Incomplete | Reranker scores medium, gentle α or abstain |
| Irrelevant | Reranker scores low, abstain |
| Contradictory | Reranker scores both high, so the **conflict check** catches it and the model abstains or reports both |

This gives the report a clean story: relevance scores handle three of the four conditions, they fail on contradictions for a clear reason, and a cheap conflict check covers that gap. Measure each part with ablations.

## How the pipeline works

```
Question → retrieve → rerank → conflict detector
                                 ├─ no conflict → answer normally
                                 └─ conflict    → strategy 1 / 2 / 3
```

Each strategy is just a different prompt given to the LLM when the detector flags a conflict. There's no extra training, so all three are cheap to run.

## The three strategies

**1. Check against memory and pick one**
*"The sources disagree. Use what you know to pick the more likely answer."*
- **Pro:** gives a single answer, which is the most useful when it's right.
- **Con:** the model's memory can be outdated or wrong, and the point of RAG is to override memory with current documents.
- **⚠️ Trap in your data:** your conflicts come from swapping the answer in a real Wikipedia passage. The original, true answer is usually what the model memorised during training, so strategy 1 will look excellent on synthetic data, but only because memory already contains the answer.
  - **Fix:** first ask every question with no passages (closed-book). Split the results into "model already knew the answer" vs "model didn't". Strategy 1 should only do well on the first group, and showing that is a good finding.

**2. Report both answers**
*"Sources disagree: one says Alice, another says Carol."*
- **Pro:** the most faithful option. It only states what the passages say and doesn't guess.
- **Con:** leaves the decision to the user.
- **Scoring:** check that both answers are mentioned and that the model doesn't add a third one.

**3. Say "I don't know"**
- **Pro:** safest. It never states anything wrong.
- **Con:** least useful.
- **Hidden cost:** if the detector raises a false alarm, the model refuses a question it could have answered.

## Evaluation

Run each strategy on every test condition (good / irrelevant / contradictory), plus one "no detector" baseline:

| Metric | What it shows |
|---|---|
| Accuracy | Right answer, where one answer is expected |
| Faithfulness | Everything stated is supported by the passages (NLI check) |
| Conflict acknowledged | When sources really disagree, does the answer say so? |
| Unnecessary refusals or hedging | When there's no real conflict, does a false alarm make the answer worse? |

**Splits:**
- model knew the answer closed-book vs didn't (this mainly matters for strategy 1)
- detector right vs detector wrong (shows how detector errors carry through to the final answer)

```

  → 2. find the core answer claim and compare with the gold answer

  → 4. check for missing required facts

- **Step 1:** prompt a small LLM to rewrite the answer as one fact per line.

- **Step 5:** for example, core answer wrong → 0. Core answer right with any contradicted claim → 3. Core answer right with a missing supporting fact → 4. And so on.

|---|---|---|

> Human: "A man throwing a frisbee in a park."
> VLM: "A man throwing a frisbee in a park, with **trees** and a **bench** in the background."

If the trees and bench really are in the photo, comparing text with text wrongly marks them as hallucinated, just because the human didn't mention them. - **Easy part:** labelling with CHAIR-style matching against annotations and captions. This is existing work, so cite it.
- **Research part:** a detector that finds hallucinations **without** human labels, from the VLM's own signals, and the test of whether it carries over to other datasets and to attributes and relations.

## How the VLM writes
It writes one word at a time. For each next word, it:
1. reads the photo plus everything written so far
2. produces a set of internal numbers (the hidden state)
3. uses those numbers to choose the next word

```

The numbers that **choose** "dog" exist **before** "dog" is written.

## Normal detection vs early warning

| | Which numbers the probe reads | When it knows |
|---|---|---|
| **Normal** (the earlier plan) | The numbers just after "dog" is written | After the mistake is made |
| **Early warning** | The numbers that chose "dog" (one step earlier) | Before the mistake is shown |
| **Earlier still** | The numbers 2–3 words before "dog" | Well before the word appears |

```
VLM picks next word "dog"
   ↓
Is "dog" an object word? (check against the COCO word list)
   ├─ no  → keep it, continue
   └─ yes → run the probe on the numbers that chose it
             ├─ probe says "real"      → keep "dog", continue
             └─ probe says "made up"   → reject "dog", ban it, let the VLM pick another word
```

The probe is tiny, so running it at every step barely slows generation.

**What to do when it says "made up":**
- **Ban and re-pick:** block that word and let the VLM choose the next most likely one.
- **Stop:** end the sentence there.
- **Feedback:** your earlier loop, so the VLM rewrites with a note.

- **Train:** one probe per offset: 0, 1, 2 and 3 words before each object word.
- **Plot:** probe accuracy (AUROC) against how many words early.

  - If it drops to chance, the decision to hallucinate happens at the last moment. That's also a valid finding.

It won't get everything right. Long, detailed captions are exactly where VLMs hallucinate most. But it might get *too much* right, leaving too few mistakes to train on, so here's how to check for that and what to do.

## Check before the full run
Run a **pilot on 100 photos** first (about 5 minutes) and count the hallucination rate.

**How many mistakes we need:** roughly **500 or more hallucinated object mentions** in the training split for a stable probe.

| Hallucination rate | Mentions (4,000 photos × ~10 objects) | Enough? |
|---|---|---|
| 10% | ~4,000 | ✅ plenty |
| 5% | ~2,000 | ✅ fine |
| 2% | ~800 | ⚠️ borderline, so use more photos |
| <1% | <400 | ❌ use the options below |

## If Qwen is too accurate (easiest first)
1. **Longer captions:** ask it to "Describe every object in the image in detail" and raise `max_new_tokens` to 512. Hallucinations rise sharply in the later parts of long captions.
2. **More photos:** go from 4,000 to 8,000. The cost is GPU time only.
3. **Lower image resolution:** Qwen2-VL lets you cap the image size (`max_pixels`). Fewer image details lead to more guessing. Keep the setting fixed and report it.
4. **Switch to a model that hallucinates more:** `llava-1.5-7b` in 4-bit is the standard VLM in hallucination papers. It's slower but reliable for producing mistakes.
5. **Add POPE-style yes/no questions:** "Is there a fork in this image?" for objects that often appear in similar scenes but aren't in this photo. These trigger hallucinations on purpose.

## If it still barely hallucinates
That's a finding in itself ("a 2B VLM rarely hallucinates objects in COCO captions"), but it's a weak base for the project. Options 3 and 4 make that outcome very unlikely.
